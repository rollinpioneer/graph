# F1 零训练精度诊断与最小修正

结论：原缓存由六通道 cuDNN TF32 卷积、随后 FP32 加权求和产生。P0 将它折叠成 FP64 单一仿射式，改变了舍入路径。权重与缓存一致；原来的误差不能归因为缓存损坏或加载了错误权重。

## 原因与已实施修正

原源代码先做 `Conv1d(64,6,1)`，再以 FP32 的 `[0,.2,.4,.6,.8,1]` 对六通道加权求和；不存在 softmax。导出的 score64 来自该卷积输入的 pre-hook。P0 的 `c @ W` 与 `feature64 @ effective_weight` 在实数代数中等价，但与 TF32 的乘法舍入、FP32 的累加顺序不等价。提升到 FP64 或仅关闭 TF32 不能恢复已经生成的历史分数。

新增 `code/score_replay.py`：使用固定 EG-B 权重、原 64→6 卷积、显式 cuDNN TF32 和 FP32 加权求和，在缓存特征上重放；不会运行 EG 主干。`code/f1_full.py` 同时保留原折叠仿射与修正重放两组指标，避免把重放通过误当作 P2 纯仿射前提通过。旧 P0 数字保留为真实历史结果。逐帧明细留在服务器 `full_frames.json`，摘要及其 SHA256 随此卡归档。

复现：在服务器加载 `eg_sub25_b_f05_repl_v1_20261019/activate.sh` 后执行本目录 `code/f1_full.py`。需要兼容 CUDA/cuDNN；本次为 PyTorch 2.5.1+cu121、cuDNN 9.1。代码拒绝静默回退 CPU；不同软件/硬件应重新通过同一数值门槛。

## P2 原门槛仍阻断

12 个 C3 场景首帧 ×3 个冻结 G 头上，原折叠仿射的 F05 误差范围为 0.0002051123–0.0002848437，36/36 超过 I1 的 1e-9；Top-1 在这 36 个检查中均未变化。原路径重放的 F05 误差为 0，Top-1 相同。

这里检测的是原初始化的有效仿射分数，未重新拟合 α/β 或训练参数。原方案的特征标准化反变换在代数上仍是该仿射式；正 α 与平移 β 在 F05 的非退化 z 标准化中消去，因此 fit 矩匹配无法消除本次 TF32 差异。不能据此断言所有可能的 65 参数模型都无解，但原方案指定的初始化没有通过。

因此状态为 `BLOCKED_PURE_AFFINE_INITIALIZATION`。F1 原阈值 1e-4、近并列界限 1e-5、I1 阈值 1e-9 均未修改。重放修复不自动批准 P2，也不是 E_act 无效的实验结论。

## 最小后续方案（本轮未实施）

若要保留历史基线并满足 step-0 精确一致，可把 E 侧改为 `s_TF32(t) + delta_w^T * t_standardized + delta_b`，新增 65 个参数初始化为零，随后再施加 fit 确定的正仿射缩放。这保留 65 个可训练参数，冻结的 TF32 基线可以缓存；但函数类变为“冻结原分数 + 仿射残差”，已经不同于原定纯仿射读出，需明确修订实验定义后才能运行。不能悄悄用此方案解除原 P2 阻断。
