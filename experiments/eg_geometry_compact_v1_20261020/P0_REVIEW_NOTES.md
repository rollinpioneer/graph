# P0审批补充说明

本轮批准前仅执行3帧输入核验、成本估计与临时容量探测，正式optimizer更新为0。具体方法和A/B判据以EXPERIMENT_CARD.md与frozen_config.json为准，原文件保留冻结散列。

P2应使用同一C3开发口径的保护基线：O AP42.280472、Top1 42.827691%；G AP44.771774、Top1 47.526042%。来源见results/reference_C3_summary.json。用户提供的G AP48.241/Top1 54.99%来自C4，不能拿它与C3的C/S结果跨集相减。本轮不运行C4。

Top1完全沿用旧代码：非空、非碰撞，且0<mu<=0.4000001；官方AP摩擦阈值和累计精度定义保持原样。负值mu不代表合格。

临时GPU容量探测为单帧形状张量的有限梯度/显存检查，不执行optimizer.step、不保存模型；不能把此组批当正式训练。正式训练必须重建原24576组顺序，逐种子检查原索引流与scene/frame/candidate身份流，按旧O跨帧混合采样。

P0的保守包围球只减少S区域外的查询点，区域、配额、排序和最终输入均不改。C保留完整0.16米邻域。原始NumPy/完整查询实现与初始P0结果保留，等价回执在P0_C_kernel_equivalence.json。P3所有测速帧再次比较S采样点/mask与canonical完整查询；存在差异时不能用该加速分支宣称高效。

S借鉴直接处理点集与排列不变性的思路，参考[PointNet原论文](https://arxiv.org/abs/1612.00593)；抓手局部点云用于质量判断的背景参考[PointNetGPD原论文](https://arxiv.org/abs/1809.06267)。本卡8维输入、五区配额、max+mean压缩及与冻结EG特征拼接为本轮设计，不声称照搬论文完整网络。

本轮上限2 GPU进程小时、70 CPU worker小时、15GiB包含P0，不能沿用其他卡的预算修订权限自动扩展。审批后可按实时资源调整并行，不改变方法、数据、种子、1000步或数值判据。Git仅作本地归档，远端仍禁止自动推送。
