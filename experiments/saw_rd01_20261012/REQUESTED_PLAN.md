# SAW-RD-01：从基线复现到问题位置诊断

日期：2026-10-12（Asia/Taipei）  
状态：设计稿 v1.0；本文件不代表已部署、已训练或已发现机制。  
研究目标：先建立可训练、可核验、可诊断的 SAW 平台，再定位失败来自哪些环节。本轮不把论文新颖性审查作为启动前提，不要求预先设计新方法。  
范围变化：从 EC-Diffuser 视觉机械臂数量扩展，转向状态输入 PointMaze 的离线目标条件学习。两者不是同一任务；本轮不宣称机械臂泛化或简单任务零样本组合。

## 0. 权限、资源与版本

### 0.1 预算提案

完整计划预算建议为 **12 GPU小时**，其中资格核验最多2、两条正式基线训练合计最多8、冻结评估/原因诊断最多2。这里是待批准的资源上限，不是耗时保证。此前约2 GPU小时不能默认为已授权12小时。

如果仅有原先2 GPU小时的授权，执行到环境、数据、训练测速与诊断接口检查即停止，保留测量结果，等待完整训练预算获批。不得用欠训练模型的低成功率冒充作者方法缺陷。若完整预算明确获批，则阶段之间普通研究判断自主推进，不逐项等待确认；超预算、越权限或重大协议变更仍须停止。

每个训练作业使用单GPU；任务相关进程的合计显存沿用12 GiB上限。并行训练不能通过换卡绕过合计上限。测得两个作业可以同时容纳才并行，否则串行训练、并行CPU分析。GPU小时按实际使用的各GPU驻留时间保守计费，另记墙钟和CPU成本；CPU评估不因GPU空闲而被遗漏。

CPU环境/接口专门排障最多两个有依据的修正循环或90分钟，先触及者停止；不是整项CPU分析的硬性90分钟上限。不得破坏共享环境、停止他人进程、访问私钥内容、覆盖历史成果、强推或合并。

## 2. S0：环境、数据、配置与测量资格

### 2.1 环境与数据检查

- 在隔离目录准备官方代码、依赖和两个数据集；先不完整训练。
- 核对状态观测与目标字段、动作语义、归一化、奖励/掩码、终止/截断、最大回合步数、5个评价目标。
- 数据索引至少保留trajectory ID、step ID、terminal、原始完整observation/action/next_observation。不将不同轨迹首尾拼成真实转移。
- 显式保存场景/环境、训练采样、JAX、评价、诊断采样随机数。不同批量槽位或评价开销不能偷偷改变训练数据流。
- 用任务达标、未达标和简单无障碍短程正例检查评价器；不改成功阈值。
- 对日志开关做小型一致性检查。诊断应使用独立随机数或冻结后离线执行，避免增加日志改变原训练路径。

### 2.3 资源测速

使用真实batch和网络进行JAX编译、前向/反向/优化器更新，另测一轮小规模完整评价。单独报告编译、稳定更新、数据采样、CPU/GPU评价和日志成本。对JAX异步计算同步计时。

预先固定最多10,000次更新的测速；这是工程样本，不作为科学结果。完整训练从预登记种子初始化，或仅在数据流、优化器、随机数和更新计数全部准确恢复时续接，不能混淆。

估算完整运行：
T ≈ 编译加载 + 1,000,000×稳定单更新耗时 + 预定评价总成本 + 保存/诊断开销。

估算不是完成保证。若任一正式训练预计超过4 GPU小时，或两次训练合计超过8，先报告预算不匹配，不启动必然超限的完整运行、不静默缩小模型。达到硬上限需保存退出，标记预算截断而不是科学失败。

## 3. S1：建立可信原版模型

1. 运行R-N与R-S；资格通过后无科学依赖、显存允许则并行。
2. 保持原始训练数据、目标采样、损失、优化器、模型和评价主协议。
3. 在100k、300k、500k、1M更新保存检查点及完整状态；主结果使用预定1M终点，不事后选最好检查点。
4. 保留每100k原有评价；每项任务50回合。视频可以设0，额外观测放在冻结后的独立评价，明确这是记录开销调整，不是模型或成功规则更改。
5. 记录value_loss、low_actor_loss、actor AWR loss、waypoint loss及各自advantage，不能只保存合计loss。
6. 保存全部终点评价逐回合轨迹和初始化信息。训练中评价是开发材料，不再当作新确认。
7. 冻结主模型后另用预登记新评价随机数进行最终评估：每个环境5任务×50回合；逐任务报告，不只报总均值。

结果标签：
- RUNNABLE：能运行、有限数值；不是可信性能。
- SINGLE_SEED_BASELINE：完成正确预算的原版训练、指标已核查；可做本权重诊断。
- PROTOCOL_APPROXIMATION：Stitch配置有未确认项；允许诊断，限制原论文比较。
- UNDERTRAINED/BUDGET_STOP：训练未完成，不能拿低分作为SAW机制缺陷。
- PAPER_LEVEL_REPRODUCTION：本轮不宣称，未做论文规模多训练种子。

如果Navigate明显不学习且Stitch也不学习，优先有界检查数据、目标、奖励与配置，而非直接研究“SAW全部失效”。不要把低Stitch分数当作代码正确的证据。若只一个训练种子异常，不根据论文均值±标准差机械判错；记录差异，必要时单独申请第二训练种子。

## 4. S2：建立失败地图与发现/确认分工

对固定模型的全部轨迹进行分析，包括成功、失败、未触发。按目标、路径需求、转弯/通道、数据支持程度分层。

主指标保持环境成功率；补充终点距离、首次达标时间、路径长度、反复访问、贴墙/无有效移动时间、每回合代价。最短路应遵守墙体和可通行空间；欧式距离变小不一定是正确推进。

地图路径仅是诊断参照，不是原策略拥有的输入。不得把几何最短距离等同于折扣价值真值；速度、动力学、数据支持与奖励终止均影响价值。

事件阈值在独立校准集上确定，之后冻结。物体不动类机器人阈值不能直接照搬PointMaze。区分正常转向/减速与真正异常。典型视频只是说明，所有主分析用预定全集。

数据角色：
- 训练集不额外删减；全量官方训练数据保留。
- 训练日志/中途评价/首批离线探针是发现材料。
- 机制确认使用预登记新状态-目标、环境随机数或未用于选假设的官方验证轨迹。若验证轨迹已被训练过程日志查看，不能称完全未消费。
- 多个评价种子只说明固定权重的表现，不替代多训练种子。

## 5. S3：四个环节并行定位，不预设采样偏差是根因

官方SAW训练通路可按如下关系诊断：
离线数据/目标与waypoint采样 → 价值优势及权重 → 短目标策略提供动作目标 → 最终策略学习并输出动作。

这是诊断分解，不表示四个模块互不影响，也不表示模型训练依次进行。

### D1 数据支持与waypoint候选

问题：有效路线是否在数据中以可利用的局部片段存在？原采样是否经常没有提供有用的中间状态？

首轮每数据集固定4,096个训练式(s,g,w)探针；保存采样索引，w必须来自真实HGCDataset规则。另固定最多128个诊断(s,g)状态-目标组，每组最多16个候选，不做全数据两两距离暴力扫描。

比较：
- 同轨迹按官方规则取得的waypoint；
- 从数据内检索、通过可达性核验的局部候选（只作诊断）。
记录候选对路线推进的覆盖、分布、轨迹来源、与评价目标的支持关系。

限制：
- 地图有通道不代表数据有动作覆盖；占据图覆盖不代表轨迹可拼接。
- XY接近不代表状态等价；需要速度、穿墙检查、可行局部转移。
- 一张近邻图看似不连通，不证明不存在解；图边看似连通，不证明策略能执行。
- 推理成功一次不证明改变训练采样必然改善最终策略。
- 若数据本身不足，优先将瓶颈标在支持范围，不能强行称网络表示错误。

### D2 价值估计与权重

问题：候选里存在可行的有用waypoint时，价值是否把它压低或把无用候选抬高？

在同一(s,g)、同一候选集合上查询两个V估计、其均值、V(w,g)-V(s,g)、权重截断前后数值，记录
rho=min(exp(kl_alpha*(V(w,g)-V(s,g))),100)
及one-step AWR相应权重。

短/长目标分组；对同状态候选做排序核查，避免直接比较不同s的绝对数值。报告重复错序、估计分歧、饱和/集中程度、反例；不要仅报告“平均V更低”。

少量真实可行局部推进和已知错误/不可短达候选作为测量参照。价值并不等于几何最短距离；detour最初远离终点不自动是错误。Bellman残差小也不证明长期价值正确。

只有候选可行性、进展与数据支持有相应证据时，才能将排序问题写为具体价值线索；否则标未知。

### D3 短目标策略的局部控制

问题：原版low_actor是否确实掌握了需要的局部能力？

预先选取最多64个短程(s,w)对，分层包含数据内真实未来目标、诊断状态附近有支持的目标，以及不同目标类型/转弯条件。数据未来状态“曾被行为策略到达”只是可行性线索，不是low_actor必然能到达。

在完整状态合法初始化后，比较：
- low_actor(s,w)；
- 同权重actor(s,w)，相同目标、相同预算；
- 必要的简单可行性参照，只有诊断用途。

默认局部预算与原subgoal_steps对应；末端截断的waypoint记录真实跨度。不要事后给失败组加时直到成功。需要额外预算对照时先登记。

记录实际局部到达率、轨迹、贴墙、动作输出、速度和目标条件。对数据内与评价访问状态分别统计。

没有可靠状态重置时，改为可核验的固定初态完整运行；不要再次无边界修复快照。取得一批新轨迹不等于重现旧失败片段。

若原短目标策略也不会完成该局部动作，先定位局部学习/覆盖，不把长目标失败归咎于最终策略蒸馏。

### D4 短目标知识是否进入最终策略

问题：有效候选有支持、权重合理、low_actor有效时，最终actor是否仍系统性输出无效动作？

固定(s,g)，分析相关(s,g,w)训练支持及对应low_actor动作目标、实际actor动作、加权匹配误差和不同候选动作的一致/冲突。默认const_std路径实际使用动作均值平方差，应沿实现记录，不编造另一套KL。

特别区分：
- 有用动作目标根本未被采样到；
- 有用目标出现但权重很低；
- 有权重但教师动作不可靠；
- 教师动作合理，学生未学到；
- 多个有效但不同路线的动作目标发生冲突；
- 只在未覆盖的评价(s,g)上不同，而训练支持内拟合正常。

“近目标能完成、远目标不能完成”只能说明能力差异，不独立证明蒸馏失败。动作不同也可能是多条合法路线。需要同一路径条件、训练支持与真实进展的补充证据。

## 6. S4：最多一项条件性区分实验

完成D1—D4之后，不强制四条线各训练新方法。选择最有依据的一个关键分歧，运行一张冻结附表；没有定位依据就报告尚未判定，不重复盲试。

附表必须在结果可见前写明：机制候选、竞争解释、唯一主要改变、原版/简单对照、状态-目标与种子、主指标、诊断特权、更新/控制预算、停止与解释规则。

候选例子，不是已批准的固定改进：
- 数据候选缺失 vs 权重排错：固定候选和其可执行性，分开比较原候选覆盖与原V排序。不能同时替换候选和V后归因其中之一。
- 局部策略失效 vs 最终策略失效：固定同一真实可达waypoint，比较low_actor与actor的局部执行，再核查actor对最终目标的行为。
- 若“教师有用但学生未保留”已有证据，可在副本中冻结V和low_actor，仅做原目标/一个明确替代诊断目标的等更新短训练对照。最多50k更新/臂，共不超过100k，含在2 GPU小时诊断预算内。两臂相同初始化、数据量和种子，独立状态/目标复核。需要本卡完整执行授权及冻结附表；这是局部识别实验，不是正式新方法训练或整套离线算法成绩。

使用地图、数据检索得到的优选waypoint、真实环境回报选动作、仿真真值等，都必须标为oracle诊断。不得把额外信息或搜索后的分数写成原信息条件下的算法提升。

旧checkpoint只能读，干预副本独立保存。冻结模块下的局部结果只适用于该条件，不能外推为联合训练系统唯一根因。

新rollout总预算优先控制在128个短片段以内，不与D3重复计数；环境CPU开销另记。所有样本按预登记清单完整保留，不在同状态试到成功，不事后选择最佳动作/随机种子。

## 7. 判定：找到“问题位置”即可，不要求唯一根因

| 证据组合 | 允许结论 | 不能直接说 |
|---|---|---|
| 有用局部连接在数据支持中，但原waypoint采样覆盖稀缺；局部策略可执行 | 采样支持是可干预的候选限制 | 修改采样必然提高整体性能 |
| 候选可行且有用，原V反复错序，控制后差异仍在 | 价值/加权环节有具体问题证据 | 一定要换某种价值网络 |
| 给定真实可达短目标low_actor也不成功 | 局部策略能力或覆盖不足 | 长目标蒸馏失败 |
| 可用教师目标、合理权重与训练支持均存在，actor未保留能力，局部对照支持 | 策略提取/训练引导存在局部失配 | 已证明所有Stitch失败都由它造成 |
| Navigate和Stitch都异常且资源/协议未过关 | 复现或训练问题待查 | SAW算法无效 |
| 原困难没有在可信训练后出现 | 当前配置/种子未复现该现象 | 必须继续调参把低分找回来 |
| 仅有相关性或诊断工具无判别力 | 描述性结果、机制未知；列出缺口 | 自动追加下一轮同质探查 |

只有本权重证据时明确写“单训练种子”。稳定机制与论文主张以后仍需独立训练种子和适当外部任务，但本轮不把这些全部启动。

新颖性审查延后到有具体问题位置时，再进行与该机制有关的有限排重；不在本轮重新泛搜几十篇论文。

## 8. 并行与顺序

- 代码/数据审查、日志开发、两数据集CPU分析可并行。
- 资源/评价器通过后，R-N与R-S可并行训练；显存合计超限则串行。
- checkpoint可读后D1—D4尽量并行，必须共用相同的样本ID、坐标与目标语义、checkpoint身份。中途分析不能反过来改基线训练。
- S4依赖S3结果，不能为并行提前预选“解决方案”。
- 各训练/分析使用独立随机数和只读输入、唯一输出目录，避免日志或批量改变数据采样。
- 不为了并行额外增加算法、环境、样本或预算。
