# SAW-RD-01 frozen execution protocol

User authorization: two separate seed-0 baselines and bounded diagnosis, aggregate 12 GPU hours, aggregate task GPU memory 12 GiB. Phase caps: S0 2 hours, S1 8 hours (each formal job at most 4 hours), S2–S4 2 hours. CPU environment/interface repair cap: two evidenced cycles or 90 minutes. One cycle fixed the incompatibility between JAX 0.4.35 and the namespace packaging of CUDA NVCC 12.9 by pinning NVCC 12.6.85. No official algorithm changes.

Archive branch `codex/saw-rd-01-20261012`; official SAW and local OGBench source both `3535a16c901e5de1233ac5a586401b3ddfa5e30d`. Local editable OGBench reports version 1.1.5. Dependencies are fully enumerated in `requirements.lock.txt`; primary versions and data identities are recorded in `results/dependency_versions.json` and `results/DATA_AUDIT.json`.

Both runs use the complete default `agents/saw.py` config: 1,000,000 joint value/low-actor/actor/waypoint updates, batch 1024, lr 3e-4, three 512-unit layers, layer normalization, separate goal encoders and 10-dimensional normalized representations, two value heads and their targets, discount .99, expectile .7, low/AWR/waypoint temperatures 3, subgoal horizon 25, constant actor std, no visual encoder. Exact full config is retained in qualification JSON and each formal run. No pilot checkpoint resumes into formal training.

Training data and original HGCDataset sampling stay unmodified. Explicit NumPy/Python training seed 0 is set before the one-example initialization batch; agent initialization/JAX RNG seed 0. Different datasets have independent models and optimizer/RNG state. Validation, development evaluation, and diagnostics save and restore the global NumPy state so they cannot change training samples. Logging-on/off exact parameter/optimizer/RNG consistency is checked by the pilot. All required components of the original loss are logged separately every 5,000 updates.

PointMaze state is the full two-dimensional qpos observation; simulator qvel is separately retained for state resets and trajectories. Dataset NPZ includes qpos and qvel. Action is clipped to [-1,1], position increment .2 times action, followed by the official MuJoCo steps. Goal threshold stays 1.0, all five official tasks, horizon 1,000, original initial/goal noise. Sparse training reward and mask come from equality of the sampled state and goal index, not from raw trajectory terminal flags. The official compact-loader terminal remapping is preserved. Raw terminal rows are marked as having no valid next transition in the server-side index.

Development evaluation occurs at step 1 and every 100,000 updates, 50 episodes per task, temperature 0, CPU evaluation, no video. For deterministic temperature 0 the clipped distribution mode equals the official sampled action. Full trajectories are retained. Evaluation seed is `71000 + 1000*dataset_index + update_counter` (Navigate index 0, Stitch 1). Reset scene seed per episode adds `10000*task_id + episode_id`; action-space seed adds 2,000,000. Global NumPy goal-noise RNG is separately seeded for each evaluation. These explicit independent streams are an instrumentation choice and are not claimed to reproduce the authors' original random realization.

Full checkpoints at 100k, 300k, 500k and 1M retain agent parameters, target parameters, optimizer, JAX RNG, NumPy/Python RNG, scene/action-space RNG, scene state, goal, update counter. Resource stops request a graceful checkpoint. Hard guard checks every two seconds, reserves 90 seconds for shutdown, and charges each job's whole wall time conservatively, including CPU evaluation while the GPU agent remains resident. The guard includes all task active PIDs in aggregate memory and does not touch other users' processes.

Final confirmation after freezing the 1M models uses fresh evaluator streams: Navigate 91001, Stitch 91002, five tasks × 50 episodes. Development evaluations are discovery evidence. One training seed is a SINGLE_SEED_BASELINE, not the paper's cross-seed mean. Stitch uses the same preregistered implementation defaults and is additionally PROTOCOL_APPROXIMATION: the official hyperparameter script and Appendix G Table 2 do not provide a separate SAW Stitch command/config. No tuning toward the paper's low Stitch score.

Diagnosis seeds: sampler Navigate/Stitch 41001/41002; discovery candidate states 101001/101002; confirmation candidate states 111001/111002; local rollouts 121001/121002. D1 retains 4,096 original-rule samples per dataset. D2/D4 share these IDs and frozen checkpoints. Candidate probes at most 128 state-goal pairs across both datasets and at most 16 candidates each; data-future full-state waypoints establish empirical transition support, while geometric/BFS map distances are diagnostic oracle information and never value ground truth. D3 reserves at most 64 state-waypoint pairs across both datasets, each compared with low_actor and actor under identical full state, waypoint and at most 25 steps: at most 128 local rollout segments total. No extra rollouts remain for a second intervention by default.

Any intervention requires a separately frozen `INTERVENTION_CARD.md` after D1–D4 evidence and before its outcomes, at most one change, independent confirmation states/goals, budget checked against S2–S4 and aggregate caps. No credible discriminating hypothesis means no intervention, with the reason recorded. No QRL, extra training seeds, architecture search, or new method is authorized in this round.

Primary protocol sources: [official fixed hyperparameter script](https://github.com/johnlyzhou/saw/blob/3535a16c901e5de1233ac5a586401b3ddfa5e30d/impls/hyperparameters.sh), [paper Appendices F/G/J](https://arxiv.org/html/2505.14975v3). The paper is protocol context; its performance numbers are not measurements by this project.
