# B1 原版方法审计：排序监督与实际搜索表现

标签：Opt Rank（Hao 等，IJCAI 2024）与 Chrestien 等（NeurIPS 2023）均为 `PAPER_ONLY`（论文读到，未找到官方实现入口）；GOOSE 的排序数据生成与 rank-SVM 为 `OFFICIAL_CODE_AUDITED`；D0/T1-S 为 `CP_DISR_ADAPTATION`。

## 1 论文核查（B-P）
| 问题 | 回答 | 位置 |
|---|---|---|
| 父子/兄弟/跨路径/离轨状态如何得到约束 | Opt Rank：对最优计划上每个状态 s_i，约束 s_i≻父 s_{i-1}，且 s_i≻其父的兄弟；**跨路径关系靠传递性得到**，兄弟之间不排序；标签只用相对序（-1/0/+1）；离轨状态=兄弟，用 h* 标注“计算昂贵” | Hao §3, §4.3 |
| 理论 | 单位代价、全序（总拟序）、固定并列规则时，**最优排序**的 GBFS 返回最优计划（Thm 1）；对**训练得到的模型无保证**（§4.1 只保证返回拟序；§6.3“不保证学到的是最优排序”） | Hao §3, §4.1, §6.3 |
| 理想排序与 OPEN | Chrestien：只要求每一步 OPEN 中计划上的状态严格优于计划外状态，计划上状态之间不比较；计划外状态之间的次序在定理里不需要；多条最优计划时零损失可能达不到；GBFS 的完美排序可能不存在 | Chrestien Def 1/Thm 1, §8.3–8.5 |
| 训练状态来源与损失 | Opt Rank：最优计划状态+兄弟；偏移 sigmoid + MSE 的成对 Direct Ranker，Adam，批量共享嵌入；Chrestien：OPEN 列表对 + 距轨迹 1 的状态，logistic 代理损失 L01/L*/L_gbfs/L_rt | Hao §4, §6.2；Chrestien §4.1, §6 |
| 搜索调用 | 成对器经 Lemma 2 变成标量 r(s)=w·nn(s)，按 r 排序 OPEN；每状态一次网络评估 | Hao §4.2 |
| 作者承认的限制 | 仅单位代价；学到的排序未必最优，Opt Rank(GOOSE) 有时计划更贵；仅领域特定排序；hff 总体仍最好 | Hao §6.3, §7 |
| GOOSE 官方排序数据（代码） | 每题一条最优计划；good=计划后继，maybe=其余后继（未知，当作更差），bad=父状态；对 (good,maybe)、(good,bad)；重复对记数但 `fit` 不传权重；LinearSVC hinge C=1 无截距 | `classic_ranking_dataset_creator.py:29–76`；`rank_util.py`；`rank_classifier.py:19–62` |

## 2 三列对照：原作者方法 / D0 ACTION / T1-S
| 维度 | 原作者（Opt Rank + GOOSE 官方数据） | D0 ACTION | T1-S |
|---|---|---|---|
| 数据来源 | 每题一条最优计划的状态与兄弟 | Train96 的 457 条轨迹（96 专家+361 偏离），精确 d*，5979 个决策、1919 个唯一父状态 | 同 D0 |
| 监督信息 | 相对序；GOOSE 里兄弟视为更差而无标签 | 精确 d* 严格序；最优集合 NLL + 严格兄弟对 softplus；权重 1/(轨迹长×批) | 把每个决策 25% 的严格兄弟对换成同题不同父、d* 更大的严格对（固定哈希次序）；分母不变 |
| 比较对来源/候选集合 | 父子+兄弟；跨路径靠传递性（理论），不显式训练 | 同父严格对；无显式父子项（V(s) 在 softmax 与对差中抵消） | 加显式跨父对，两端可均为计划外状态 |
| 模型/更新预算/检查点/搜索协议 | 各自的模型与协议 | 同一架构，4100 更新，选 820 | 同架构，选 2460；共同 eager GBFS |
**不能把 D0→T1 的差异当成原排序机制的消融**：T1-S 在监督、采样、检查点上都与 D0 不同。

## 3 T1-S 差异与既有结果复核（B-E，仅用已保存数据，见 `B1/pair_to_search_evidence.csv`）
1. **唯一对 ID**：D0→T1 的 INV→COR（修复）与 COR→INV（损伤）共 173 个唯一对：跨父 112+36=148，同父 17+8=25；全部精确标签；**无并列介入**（神经分数连续，原容差与严格比较给出同一计数）；与保存的 `b_pair_outcomes` 逐行一致（0 个不一致）。
2. **分层**：跨父修复 112 = Train96 题 85（两端都是训练状态的 57）+ Struct 27；跨父损伤 36 = Train96 题 30（15）+ Struct 6。没有 Joint 题（Joint16 无变化）。**库 B 的 Train32 是训练题，离线改善中相当一部分是样本内拟合**，不能当泛化证据。d* 差（含同父，修复 129/损伤 44）：修复 1:75/2:34/3:12/4:5/5:2/6:1；损伤 1:29/2:12/4:2/5:1。
3. **是否有实际竞争证据**：D0/T1 无任何搜索轨迹；173 个对在 Scope 候选对里 0 个出现；因此“未有竞争证据”，不是“搜索中未出现”。证据层级：E0。
4. **检查点**：820/2460/4100 下 D0→T1 跨父修复/损伤 77/28、104/25、105/27，同父 18/7、7/10、14/8 — 跨父净修复稳定为正；同父与首选层面方向不稳定。
5. **对应真实搜索事件**：任务/状态哈希/模型/检查点/协议五键不能同时匹配任何已记录事件 → 映射为空。
6. **Opt Rank 规则覆盖（粗分类，仅用库内参考计划父状态）**：跨父修复 0/112 可由“计划状态 vs 计划外状态 + 传递性”构造，损伤 1/36 可构造；同父修复 10/17、损伤 6/8 可由兄弟约束构造。含义：T1-S 修复的跨父对基本是**两端均为计划外状态**的比较——正是 Opt Rank 靠传递性不覆盖、Chrestien 的最优效率定理不需要的那类。注意：不可构造≠作者方法失败；该分类是粗的（`B1/optrank_coverage_summary.json` 的 caveat）。

## 4 离线—搜索脱节的解释层级

- E1（无）：D0/T1 没有“状态曾在某次搜索中出现”的记录。
- E2（仅旧模型）：SCOPE 的旧 DENSE/WL 快照；竞争候选是前沿子集；认证错序只有旧 WL 27 行（几乎全在 Train96 对照题），旧 DENSE 0 行，IPC 仅 1 行。
- E3/E4（无）。
- 不能回答：库 B 的改善是否出现在 IPC22 的 OPEN 中；D0/T1 的真实 OPEN 竞争；IPC 的失败原因。
