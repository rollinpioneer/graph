# Q2 事件资格、确定性重放与有限后果验证

**编号：** `CP-DISR-Q2-EVENT-REPLAY-GATE-V1`  
**日期：** 2026-10-11  
**状态：** 待批准，未执行  
**当前建议批准范围：** 阶段 G0—G2  
**阶段 C：** 仅为条件式预案；资格通过后提交具体事件清单，另行批准。

## 1．单一核心假设

在固定评分实现与完整搜索现场下，一个稳定的 D0/T1 首选分歧，除改变干预当步外，还会产生可重复的后续搜索后果。

本卡只研究**给定冻结模型、给定事件和给定后续评分器**的作用。

不检验：

- T1 监督是否普遍优于 ACTION；
- 全程使用 T1 的累计效果；
- 新排序算法是否必要；
- 单次模型差异是否由监督造成。

H3 保持未决，不通过增加重放次数冒充训练重复。

## 2．对照与替代解释

模型仅使用：

- D0@820；
- D0@2460；
- T1-S@2460。

完整权重哈希须由原回执及实际文件共同确认。

替代解释包括：检查点敏感性、浮点排序翻转、搜索现场不完整、队列语义变化、短暂重排后重新汇合、长期效果被预算截断。

OptRank 和 Chrestien 作为约束机制参照；本卡不训练原作者系统，不把 T1-S 当成其复现。

## 3．G0：旧证据与身份入口

必须取得：

1. 两轮执行卡、回执及真实提交；
2. p12 第16次展开事件的原始候选表与可用快照；
3. 重复分支日志；
4. R2 两次评分表及其比较对象说明；
5. 搜索、评分、序列化代码。

只读检查能解决的先解决，不先重跑。

特别确认：

- “逐位一致率”比较了什么；
- Jaccard 比较是否去重、是否截取同长度；
- 重复分支是否共享评分缓存或其他可变对象；
- 是否存在未保存的随机状态、插入计数和延迟评分状态。

缺少关键材料时输出 `ASSET_MISSING`，不得重建一个相似事件冒充原事件。

## 4．G1：资格筛选

### 固定范围

最多三个既有任务：

- 已知 p12；
- 首轮实际使用的两个 Struct 任务。

必须从回执取得 Struct 的确切身份。不替换为新的容易题，也不加入更多 IPC 题。

### 检查顺序

1. 首先检查旧 p12 事件；
2. 再检查两个 Struct 的前32次展开；
3. 必要时检查 p12 前64次展开。

从第一次具有多个有效 OPEN 候选的出队开始观察，取消16次展开的下限。

不完整枚举状态图。完整 OPEN 必须全部比较；超出预算则标记跳过，不用 top-k 子集冒充全前沿。

### 合格事件

- 来自真实搜索前沿；
- 两个 D0 检查点首选一致，T1 首选不同；
- 使用相同合法候选、评分方向和并列规则；
- 独立重复评分检查下，首选关系保持；
- 已能保存和恢复完整现场。

评分数值可以不逐位相同，但实际候选选择须稳定。每个候选事件使用三次独立评分检查，不能用同一缓存读取三次代替。

并列规则导致的分歧单列，不混入主事件。

### 选择规则

最多两个事件：

- p12 最早合格事件一个；
- 两个 Struct 中按任务哈希、展开序号排序的最早事件一个。

某类没有事件则空缺，不跨类补位。

**禁止查看任何分叉后的收益再选事件。**

旧 p12 属于探索性已知案例；新捕获的 Struct 事件也是开发诊断材料，不宣称独立泛化确认。

## 5．G2：可靠重放，不要求完整状态空间

完整保存：

- 规范化状态及任务身份；
- OPEN 的实际键、有效／失效条目、插入序号；
- CLOSED、重复检测、重开规则；
- 父指针、动作、路径代价；
- 目标检查时机；
- 评分缓存、批处理与其他影响运行的状态。

恢复时先检查快照一致，再检查下一次出队。

### 冻结评分语义

优先使用固定设备、固定精度、固定输入形状的确定性评分函数，并以“任务、状态、模型、评分协议”为缓存键。

未来遇到的新状态按同一规则求值，不需要预枚举。

要求：

- 缓存不可按分支分别赋予不同值；
- 评分不依赖先运行 A 还是 B；
- 缓存未命中、失败和重新求值全部记录；
- 不允许通过粗量化评分来强行消除差异。

若必须改用规范化推理路径，明确这是一项新的受控评分协议。旧 p12 分歧若在该协议下消失，只能报告协议敏感性，不能声称复现成功。

### 重放门槛

对无干预恢复路径做相同输入重复：

- 下一次出队一致；
- 最多64步公共前缀的状态、队列、父指针及计数一致；
- 无无法解释的差异。

两轮修复仍不能通过即停止，不进入因果比较。

### G0—G2 预算

| 项目 | 上限 |
|---|---:|
| 任务 | 3 |
| 前缀生成及重复恢复 | 合计6次 |
| 单次展开 | Struct 32；p12 64 |
| 模型—状态求值 | 合计8,192次，含预检和重复 |
| GPU | 0.5设备小时 |
| CPU | 2核小时 |

每个实际调用计入账本，不把内部运行藏在顶层调用内。

到限没有合格事件：`NO_ELIGIBLE_EVENT`。这是资格失败，不是否定 H2；当前 Q2 投入停止，不自动扩大面板。

## 7．阶段 C：待另行批准的有限因果比较

### 干预

每个事件从同一现场复制：

- A：按 D0@820 正常出队；
- B：只在本次强制选择 T1 提议的候选；
- A′、B′：各自完全相同的重复。

B 不删除其他候选、不永久改分、不改变后继次序。此后所有分支恢复同一 D0@820 评分和搜索规则。

不增加“全程换成 T1”的第三处理条件。

### 搜索预算

- 最多2事件 × 4分支＝8次；
- 每分支最多512次展开或120秒；
- 额外求值上限32,768次；
- GPU上限1.5设备小时，CPU上限4核小时；
- 新认证、训练为0。

包括预检在内，两阶段总计不超过2 GPU设备小时、6 CPU核小时。

### 主结果：按信息层级报告

**第一层：技术有效性**

A=A′、B=B′ 的决策序列及状态演化必须一致。否则事件无效，不给出干预效应。

**第二层：完整结局**

若两支都解出，比较剩余展开、计划长度及重复生成；计划须通过动作合同回放验证。

若只有一支解出，报告相同预算下完成状态不同。另一支的总成本是删失值，不能代入预算上限计算真实加速比。

**第三层：搜索现场重新汇合**

检查两支是否在不同出队顺序后恢复相同的、决定未来行为的完整搜索状态。

比较包括队列键、父指针、路径信息和缓存语义；只能规范化无语义作用的对象标识及序号整体偏移。先比较摘要，再核对内容。

若同一确定性后续函数下语义现场一致，可判定后续行为一致，已消耗的成本差单列。仅 CLOSED 集合或 Jaccard 相同不够。

**第四层：双方截断且未汇合**

可报告持续分歧、重复生成、队列规模、评分调用等有限窗口的因果变化。

不得把它们直接称为规划效率提升。完整搜索收益仍为 `UNKNOWN`。双方都展开512次，本身不是效率相同的证据。

不使用模型自身评分下降或未证实的 h_add 变化充当真实进展证书。

## 8．结果裁决

| 结果 | 裁决 |
|---|---|
| 没有稳定首选分歧 | 本面板无合格对象；停止当前筛选 |
| 重放不一致 | 技术无效；不能判断科学假设 |
| 两支迅速完全汇合，成本差很小 | 反对该事件具有持续影响，不推广至全部事件 |
| 完整结局可重复不同 | 支持该事件的因果作用，仍不支持 H3 |
| 同预算只有一支成功 | 支持有界完成差异，长期代价未知 |
| 两支持续不同但均截断 | 支持行为影响；效率影响未知，停止追加诊断 |
| 原作者条件已覆盖该关系 | 缺口转为学习／覆盖／实现问题，不主张新排序关系 |

投入参考线：两支均完成时，展开差同时达到20%和5次，记为“值得关注的个案效应”；它不是统计显著性或论文门槛。
