# CP-DISR C1 下一步实验文档
## 先验证第一次错误，再比较整体评分与按目标分解的评分

> 本文依据最新《CP_DISR_C1_主线复评_审稿意见_20261006.md》、附件 `loop_anatomy.py`、A03 结果及已读取的实现编写。审计的实验发现、审计的解释、本文件新增的执行设计分别标明；没有把建议当成已验证机制。

# 0. 一页式决定

**主线选择：优先研究“按小目标分别评分，再组合成整个任务的进展”。普通恢复保留为对照，不再默认作为论文主贡献。**

研究问题改为：

> 训练时只有一座需要搭建的塔，测试时要搭多座。为什么模型会拒绝一个能够立即完成某个小目标的正确动作？把候选动作的进展按目标分别计算，是否比一次性计算整个目标集合更能迁移？

本轮分两张卡，而不是同时铺开很多算法：

| 阶段 | 要回答的问题 | 工作量 |
|---|---|---|
| 第一阶段 A04P | 普通规则能修多少？错误对另一座塔的目标、当前时间输入是否敏感？ | 0 条训练；4 个控制器；一个小型配对前向检查 |
| 第二阶段 GOAL-PROGRESS | 增益来自多训练、增加监督，还是目标分解本身？ | 最多 3 条训练：M0、M1、M2 |

**三条训练不是再次训练 B2、QMARK、ASNET 排名，而是：**

- M0：原 B2 继续训练，控制追加数据和训练预算。
- M1：整体目标进展评分。
- M2：按目标分别计算、相加得到进展。

M1/M2 的输入、数据、监督、参数结构和预算相同；主要区别是“先合起来再做非线性计算”，还是“分别做非线性计算再相加”。

不做：新种子矩阵、QMARK/ASNET 重训、目标交互模块、多步搜索、n≥6 的训练、T_B 补跑、机器人恢复分支。既有思想有先例不构成否决理由；新增贡献必须用清楚的问题和匹配实验验证。

# 2. 怎样吸收审计，以及不能照抄的地方

## 2.1 采纳的研究判断

审计报告指出：B2 的 A2 失败中，首错集中为“手里拿着积木，却放回桌上，没有叠到正确底座”；最优动作常排第二；往返循环随后重复放大这个错误。审计同时指出，训练目标只有一座非平凡塔，而 A2 和原规模切片都是多塔，部分规模题还增加了塔高。[A1 §0、§一]

据此，本卡优先检验**目标集合变化下的评分**，而不是立刻增加目标之间的复杂交互或新的恢复网络。

但“评分无法组合”仍是候选解释。数据覆盖、时间特征、共享状态资源、优化和具体读出都可能参与；不能由错误动作一致，就断言找到了唯一根因。

## 2.2 审计统计中的分母必须修正

附件脚本的第一段只统计失败局；第二段“第一次错误跳过了什么动作”遍历所有出现首错的局，包括成功但绕路的局。[A2]

因此审计表中“QMARK A2 失败 17 局，但首错放下而不叠 20 局”不是可直接使用的失败占比。不得写成“20/17 个失败”。

执行时只做一次现有日志的表格整合，输出：

```text
method, split, case_id, success, has_first_error,
first_error_action, optimal_action_types,
first_error_is_put_down_instead_of_goal_stack,
best_optimal_rank, first_repeated_action_is_optimal
```

分别汇总 `all_episodes`、`failed_episodes`、`successful_detours`，所有表注明分母。不为这件事新增训练或新环境运行。审计中脚本没有直接计算的“底座”“第一次叠塔”等细项保留为审计报告发现，若需要本轮使用则由现有日志明确计算，不猜测。

# 5. 第一阶段 A04P：四个零训练控制器

## 5.1 不变项

四个控制器使用同一 B2 文件、同一原始合法动作集合、同一环境和原始步数上限 `2L*+4`。保留 GRU 的正常更新，不因为换路而清零；所有控制器按自身真实轨迹更新状态，不复制其他控制器的 hidden。

规划器仅用于生成题目、离线标签和初始参照，不参与动作选择。C3/G1 可以使用现有合同的单步名义后继，这是公开信息，不是多步搜索或规划器提示。

## 5.2 C0：原 B2

原合法 argmax，保持原 tie-break；不加访问规则、不加奖励或额外预算。

## 5.3 C1：状态—动作尝试计数

完全保留 A04 的 EDGE-RETRY 定义。[A3]

```python
raw = argmax_original_tie(logits, legal)
if visits[(state_key, raw)] == 0:
    action = raw
else:
    n_min = min(visits[(state_key, a)] for a in legal)
    candidates = [a for a in legal if visits[(state_key, a)] == n_min]
    action = argmax_original_tie(logits, candidates)
# 实际执行后递增被执行动作的次数。
```

状态键包含完整物理事实、固定目标、颜色与合同版本，不含时间或 hidden，不合并仅在同构意义下相同的不同具体状态。每局重新建表，不跨题共享。

该规则可能先干预一个正确的“重新拿起”，这是本轮要记录的现象，不在测试后悄悄改触发时机。

## 5.4 C3：已访问后继排除控制

这是访问集合思想的同模型适配，不是 KR 2023 完整复现。

- 初始状态加入 `visited`。
- 每步用原合同计算每个合法候选的单步后继。
- 删除后继已经在 `visited` 中的候选，仅在余下候选上按 B2 排序选择。
- 实际执行后将新状态加入集合。
- 若没有未访问后继：结束为 `NO_UNVISITED_SUCCESSOR`，记算法失败，不记技术缺失。

此处固定为严格排除，不在某些失败后回退成软惩罚。它可能阻止必要的回退，不保证完备性；这正是与 C1 的区别。原安全 mask 不改变，排除只是控制器自身的搜索偏好。

## 5.5 G1：直接小目标进展规则

设 `Sat(F,G)` 为当前已满足目标原子的集合。构造：

```text
P = {合法动作 a:
     Sat(F,G) 是 Sat(F_after(a),G) 的真子集}
```

若 P 非空，在 P 内按 B2 分数选择；否则沿用原 B2。不是简单看目标数净增加：原来满足的任一目标被破坏，就不进入 P。

它不保证最优；可能过早完成局部目标或拒绝必要拆塔。不得将 G1 的规则用于新算法的训练标签、后处理或隐含 gate。

## 5.6 第一次选择与恢复指标分开

C1 在首次重复之前不改轨迹，通常不能改善整局最优性；C3 可能在第一次错误转移就阻止返回旧状态；G1 可以直接改第一次选择。因此不要把三者都当成相同的“恢复”操作。

主表同时输出成功、全程最优、动作数、循环、首次错误、首次干预。对每个规则输出相对 C0 的 `rescued`、`harmed` 和净收益。减少循环但不增加完成率，不称为任务能力提升。

# 6. G0：目标与时间的配对前向检查

这不是新测试集成绩，也不是新训练。只用已经消费的 A03 日志判断下一步该改什么。

## 6.1 取样范围与可复现要求

取 B2 在 A03 A2 和 B 的全部失败局的首次非最优决策，最多 70 个原始候选状态；不挑“看起来会翻转”的子集。

对每个候选先恢复：当前完整状态、目标、合法候选、base_input、**决策之前的 GRU hidden**。若 hidden 未保存，用冻结模型及已存原轨迹前缀重放网络输入，恢复旧历史；不重新启动完整环境 episode、不重做 A03 正式计分。

先在原输入上复现所选动作与概率；要求每个候选概率误差不超过 `1e-5`，合法动作相同、argmax 相同。更换精度/设备造成的不可复现样本标记 `REPLAY_MISMATCH`，不强行计入因果分母，不选择别的“好样本”补齐。

本轮新增重放只是已有测试的开发诊断；这些状态及其改目标版本全部禁止进入训练。

## 6.2 主要有效样本

主要 G0 样本必须同时满足：

1. 原选择是 `PUT_DOWN(x)`；
2. 原最优集合含 `STACK(x,y)`，且它满足当前目标中的 `On(x,y)`；
3. x 所属目标塔以外至少有另一座非平凡目标塔；
4. 原状态及输入可复现。

其余首次错误仍记录，但不套用“压平其他塔”的探针。报告原始候选数、有效数、排除原因；不预称必有 70 个有效样本。

## 6.3 四个输入条件：2×2 小检查

| 条件 | 当前目标 | 当前时间输入 |
|---|---|---|
| G00 | 原目标 | 原时间 |
| G10 | 其他塔压平 | 原时间 |
| G01 | 原目标 | 训练轨迹的参考时间 |
| G11 | 其他塔压平 | 参考时间 |

审计建议三种前向；本方案增加 G11，用来区分两种变化同时发生时的响应，未增加环境 rollout。

### 目标干预

保留含 x 的目标塔全部关系；将其他非平凡塔中的每条 `On(u,v)` 改成 `OnTable(u)`，原底座的 `OnTable` 保持。所有积木的目标仍有定义，目标原子总数不变；**不删除现实中的积木、不改变物理状态、不换颜色**。

重建受目标影响的缓存和目标标记，不得复用旧目标缓存。合同和合法动作集合必须相同。

规划器单独核验新目标可解，指定的 `STACK(x,y)` 仍是最优选择，而且原 `PUT_DOWN(x)` 仍非最优；否则样本标为 `LOCAL_ORDER_CHANGED_BY_INTERVENTION`，保留记录但不进入主要成对解释。

### 时间干预

仅从原 A02 的 D0 专家训练轨迹选择“持有积木、下一最优动作可以直接满足一个 On 目标”的步骤，取 `step_index/step_cap` 中位数为 τ，一次计算并冻结。不得从 dev、A03 或新确认题挑 τ。

将当前 base_input 的前两维一起替换为 `[τ, 1-τ]`，保持第三维及其余输入不变。若字段实现与此不符，以源代码字段位置做显式映射并写登记，不能猜位置。τ 参考样本为空则时间探针为 NA，不凭空填值。

四个条件都保持同一个历史前缀、同一个干预前 hidden。它只检验当前输入作用，**不能排除历史时间信息已存入 GRU 的影响**。

## 6.4 指标与解释

指定局部正确动作 a* 与原错误动作 a_bad，记录：

```text
margin = logit(a*) - logit(a_bad)
argmax_in_original_optimal_set
argmax_is_goal_stack
optimal_action_probability_mass
```

使用 logits 差为主，避免接近 0/1 的概率饱和掩盖变化。保留全部原始分数。

- G10 改善：支持该局部评分对其他目标的变化敏感；不直接证明必须采用加法分解。
- G01 改善：提示时间输入可能是更直接解释；不等于时间是唯一原因。
- 只有 G11 改善：记录联合依赖，不宣称某一个因素独立负责。
- 都不改善：该探针未支持假说；不能反推已经证明是数据覆盖问题。

不得把 G0 的改目标状态称为新的成功 episode。它只进行了评分检查。

# 8. 第一阶段之后的有限决策，不恢复无限 gate

以下是**本方案新增的工作决策规则**，不是审计已有结论，也不是显著性检验。执行前写入登记，不能看了 G0 再选阈值。

G0 有效样本至少 12 个才做数值方向判断，否则标 `INSUFFICIENT_PROBE`。

定义每种单因素变化的支持条件：

- 局部正确动作翻为 argmax 的比例 ≥25%；或
- 对至少 60% 有效样本提高 margin，且 margin 变化中位数 ≥1.0。

据此输出：

| 状态 | 条件 | 下一步 |
|---|---|---|
| `GOAL_PROGRESS_READY` | 目标干预达到支持条件；时间可有可无 | 推荐执行已写明的三条训练；有时间响应则作为已披露混杂，M1/M2 同时不输入时间 |
| `TIME_INPUT_FIRST` | 只有时间达到支持条件 | 不启动分解训练；带结果等待主线决定，不自动增加“去时间”训练 |
| `PROBE_INCONCLUSIVE` | 两者都未达到；或只有联合作用 | 不声称假说被推翻；本卡完成后等待是否投入三条训练的明确选择，不继续扩大探针矩阵 |
| `INSUFFICIENT_PROBE` | 有效样本不足或参考时间缺失影响解释 | 完成规则成绩，说明限制，不补跑旧测试重建机制 |

若 C3/G1 在 Pilot 核心切片上达到 ≥90% 成功，附加 `LOW_HEADROOM_FOR_SUCCESS_GAIN` 提醒：后续算法仍可研究首次最优选择或内部化规则，但不能预设能在完成率上超过简单规则。不因此自动抹掉该方向的意义，也不另造更难题来让基线失败。

第一阶段输出后，只有用户已授权完整条件执行、且状态为 `GOAL_PROGRESS_READY`，才能自动进入第二阶段；否则按回执停下。**这一选择决定是否花三条训练预算；不是要求每个模型考试超过某分数才能看结果。**

# 9. 第二阶段：具体算法定义

## 9.1 核心比较不是“新头对旧头”，而是两种聚合顺序

M1 与 M2 都从同一个 A02 B2 图编码器权重出发，使用相同单步后继与相同监督。M0 控制额外训练，并不承担严格等容量的架构对照。

| 方法 | 起点 | 读出/训练 | 作用 |
|---|---|---|---|
| M0：B2-CONTINUE | A02 B2 全部原策略参数 | 原策略读出，原最优集合模仿损失 | 控制追加训练和数据 |
| M1：GLOBAL-PROGRESS | 同一 A02 B2 图编码器 | 相同逐目标特征，先汇总向量、再计算价值 | 整体进展对照 |
| M2：ADDITIVE-PROGRESS | 与 M1 完全相同的编码器及新头初始化 | 每目标先算价值、再相加 | 检验分解结构 |

M1/M2 都不附加原 B2 logits 作为残差。否则原来的整体目标路径会绕过分解约束。M0 保留原时间与 GRU 路径；M1/M2 不使用 GRU、时间、旧全目标上下文。因此 M2 比 M0 好不能单独归因于分解；**关键因果对照是 M2 对 M1**。

## 9.2 目标无关的底层状态编码

当前实现把整个目标集合的标记送入图编码器，并在读出中使用全目标均值。[R3] 若直接把这些已受整个集合影响的行相加，不能声称“加一个新目标只加一个独立贡献”。

本卡给 M1/M2 共用一个新、最小的编码入口：

1. 图保留全部原合同节点、事实、颜色、边与四层网络；
2. 进入编码器的目标标记通道全部为 0；
3. 不调用旧的带目标池化的 global readout；
4. 得到每个节点的隐藏表示 H⁰(F)，它仅取决于当前状态与合同，不取决于当前目标集合；
5. 所有目标仅在下面的逐目标索引与读出中出现。

要沿用实际合同图，不加新对象名哈希、目标编号、塔数输入或最优距离。预训练参数可微调，M1/M2 使用完全相同的可训练模块。

## 9.3 分解单位固定为目标原子

本版只按 `On(x,y)` / `OnTable(x)` 等目标原子分解，不同时尝试“按塔分解”或加入成对交互。所有目标包括已满足项都参与；必要拆目标可以出现负的进展贡献。

目标集合去重，顺序不应影响分数。原子来自完整目标图，不靠名字字符串学习身份。

对每个目标 g 构造 386 维输入：

```text
x(F,g) = [
  目标命题节点 H⁰_g(F)                 # 128
  全部 ACTION 节点的状态均值            # 128
  全部 PROPOSITION 节点的状态均值        # 128
  当前该目标原子的真值                  # 1
  目标符号（当前域为正目标）             # 1
]
```

这些全局均值只依赖物理状态，不包括其他目标标记。不要把旧 goal-conditioned 行、GRU hidden、全部目标均值或目标总数再次拼入 x。

## 9.4 两个完全等参数的新头

共享规格：

```text
phi: Linear(386,128) → ReLU → Linear(128,128) → ReLU
rho: Linear(128,128) → ReLU → Linear(128,1,bias=False)
```

M1/M2 各自拥有独立副本，开始时张量逐一相同；新头参数数均为 82,688。登记时用实际参数计数验证；禁止用无作用的 padding 参数凑公平。

```text
V1(F,G) = rho( sum_{g∈G} phi(x(F,g)) )
V2(F,G) = sum_{g∈G} rho( phi(x(F,g)) )
```

也就是：M1 先合并再判断，M2 先分别判断再合并。M1 同样使用求和而非均值，避免把“求和 vs 均值”另混成一个因素。

对于候选动作 a，使用共同进展分数：

```text
score_j(F,a,G) = Vj(F,G) - Vj(T_nom(F,a),G), j ∈ {1,2}
```

分数越大，选择优先级越高；在合法集合上 softmax/argmax，沿用固定 tie-break。每步至多编码当前状态一次、每个合法候选后继一次，可批处理，不新增多步搜索。

这是本文件新增的**可执行化设计**：将审计的“整体/分解进展头”具体化为状态前后价值差；不声称审计已经验证这套公式。

## 9.5 能保证什么，不能保证什么

固定物理状态和候选，对于不重叠目标集合 G、H，M2 应满足：

```text
score2(F,a,G∪H) = score2(F,a,G) + score2(F,a,H)
```

该等式是架构约束，可直接做 fixture 验证。空操作在状态不变时两个模型进展均为 0。

**不能由该等式推出：**最优距离可加、多塔任务必定成功、各目标没有冲突、不会循环、M2 一定优于 M1。

局部项是从整体排序监督下学习的分量，没有单目标真值校准；不得把分量数值称为“已识别的真实独立子目标代价”。共享机械手或目标冲突可能恰好需要非加性，M2 失败也是对这种归纳偏置的有效检验。

# 10. 统一数据与训练预算

## 10.1 训练任务不扩展

只允许原 144 个单塔训练目标与 n=3/4/5 状态。保留 n=3 的既有同构类重复权重及披露。不加入多塔训练目标，不使用 G0 改目标样本、Pilot80、A03 首错状态、dev 或 Confirm112 的状态做监督。

复用 A02 的 D2 全部序列。再做**一次共同数据收集**：固定 A02 B2，在 train144 上各用 C0、C3 执行一次，共最多 288 条轨迹。只是收集训练分布状态，不更新任何模型。

```text
D_train = D2_A02 + shared_C0_train_rollouts + shared_C3_train_rollouts
```

随后一次冻结。M0/M1/M2 使用完全相同文件、顺序和轨迹权重，不根据新模型的错误再做第二轮收集。

同一 (状态,目标) 的规划器标签可缓存，但轨迹历史不能因此被去掉；M0 的 GRU 需沿每条已记录轨迹运行。每条轨迹总权重相同，轨迹内按有效决策数归一化，防止循环更长的轨迹获得更大总权重。

## 10.2 共同精确标签

每个非终止状态的每个合法候选，计算：

```text
d_a = d*(T(F,a), G)
A* = {a: d_a = min_b d_b}
```

标签仅在训练损失与离线评价中使用，不进入模型前向。多个最优动作全部正确。终止状态不产生动作损失。

M0 使用原最优集合模仿：

```text
L_IL = -log sum_{a∈A*} pi(a|F,G)
```

M1/M2 使用完全相同：

```text
L = L_IL + L_rank
L_rank = mean_{d_a < d_b} softplus( -(score(a)-score(b)) )
```

对所有合法候选对计算，等距离对不加排序损失。没有严格顺序的状态，其排序损失为 0。不要把 tie-break 的唯一动作当唯一正确标签。

M0 与 M1 同时改变监督及读出，所以 M1−M0 只解释为整套进展学习改造，不单独宣称是监督作用。M2−M1 才检验分解本身。

进展算法主指标回到“第一次及后续是否选择最优动作”；恢复基线同时报告成功率。

核心集合固定为：C5-2、C5-23、S6-2、S7-2、S8-2、K6-3。按非空切片等权，不事后挑最有利的子集。

```text
S_core(m) = 核心切片成功率的等权均值
主要差值 = M2 - M1
训练控制差值 = M0 - C0
实用比较 = M2 对 C0、C3、G1
```

主表每格写真实整数分子/分母，并列 ID、A1、新组合、规模、塔数、高度。不要通过除以 ID 分数“校正”成纯表示优势。

## 12.3 行为分析从新模型自己的轨迹产生

保存完整首次错误、正确动作的名次与概率质量、是否放下而不叠、相同状态—动作重复、实际步数、必要与可避免的目标破坏。

从 M2 新轨迹上统计首错类型；不能要求 M2 必须走到旧 B2 的错误状态，也不能把模型没有访问过的状态算成它已解决。

另在已消费的 G0 状态上对最终模型做一次开发诊断可以帮助解释，但单列、不可替代 Confirm 成绩，不参与训练或 checkpoint 选择。

| M2 新组合变好但颜色反转明显退化 | `COMPOSITION_REVERSAL_TRADEOFF`；不自动调损失、加交互或重练 |
| M2 在单塔新对象上也弱 | 不把所有失败归为目标组合；报告状态覆盖、优化或去目标编码的可能影响 |
| 高度 2 的多塔能做，高度 4 才差 | 高度/更长方案是后续边界，不自动称规模失败 |
| 三个新模型都不好 | 本候选算法未获支持；保留数据，不启动第四条救援训练 |

0.10 等阈值是预先选择的工作尺度，不是投稿标准。分母不足时完整报告，不为跨阈值删题。所有标签都在全体有效结果输出后才生成。

不能由 M2 失败就证明目标聚合与错误无关，也不能由 M2 成功就说其他实现不可能有效。
