# C1-BW-METHOD-SERIAL-SUITE-V3 — technical notes and deviations

Technical gaps: **none** (43/43 stages DONE, 0 TECHNICAL_INCOMPLETE case, 9/9 trainings completed in one attempt, NaN 0, calibration temperature never clamped, no mathematical alias used, no family skipped).

Deviations from the runbook text, all disclosed:
1. **Parallel GPUs.** The runbook allows one active training and serial evaluation. After the user's instruction on 2026-10-08 ("训练/评价等任务全部采用多卡并行") the remaining independent tasks ran concurrently: GOAL_REL training and its dev selection on GPUs 1-2 while the driver trained GOAL_DENSE on GPU 0; 16 of 17 confirmation conditions on GPUs 1-7 while the driver evaluated the first one. The first seven trainings ran serially under the single driver (before the instruction).
2. **Infrastructure change during the run.** To run tasks concurrently without duplication, `scripts/c1_method_serial.py` was extended mid-run with `worker`, `parallel` and per-task `.claim` files (a stage waits for or reuses an already finished task of the same fingerprint). The change was installed after `train_GOAL_DENSE` had started (that stage ran with the old file); no model, loss, label, selection rule or evaluation code was touched, but the file hash differs from `plan/registration.json`. The semantic modules (`model.py`, `trainer.py`, `labels.py`, `heads_math.py`, `lookahead.py`, `evalkit.py`, `common.py`) are unchanged since registration.
3. **Push delay.** The first registration pushes were rejected by GitHub ("fatal error in commit_refs", then "Internal Server Error", also for a plain push of the already known base commit). They succeeded on a later retry; training started only after the registration commit `6c12b1f33` was on the remote.
4. **Dry run.** Before the real run the whole chain was executed once in a smoke mode (2 epochs, 64 trajectories, 2 problems per confirmation cell, outputs outside the repository, confirmation problems from a separate namespace); the dry-run directory was deleted. One reporting detail (GOAL_DENSE mask density reported as the REL mask) was fixed before registration.
5. **Reused references.** MG_C3 / B_G1C3 on Board48 and the 112-problem development panel are taken from the earlier cards (identical code, problems, weights), as the runbook permits.
6. **Unsummarised files.** Per-condition state-bank files on the Confirm128 problems (`confirmation/bank_*.csv`) were saved but not summarised in the narrative.
7. **Not run (by design):** first-On event variant, height-4 training, KR 2023 / external methods, second domain, extra seeds, module combinations.
