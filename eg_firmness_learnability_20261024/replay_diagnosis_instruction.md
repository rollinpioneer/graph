# 指令：定位 cal_0067_0000 复现差异，并按预定规则恢复导出

日期：2026-10-24。接 `codex/eg-firmness-export-20261024`（7ab6eec）。只用一帧做诊断，只用 CPU/GPU 前向，不训练，不评价，不做换角统计。

## 背景与首要怀疑

- 差异：pred 最大绝对误差 0.365，但 1024 个种子的 angle_index 完全一致。
- N0 缓存 `cache/train_0067_0000.npz` 是在 **RTX 4090** 上生成的（见同名 .json），这次在 **A100** 上重算。同样开着 TF32，但不同显卡上的 TF32 和 MinkowskiEngine 卷积数值不完全一致，argmax 接近并列的地方可能翻转。
- angle_index 全部一致，说明种子点和大部分输出没变。0.365 这个量级最像"少数种子的视角选择翻到了相邻视角"：旋转矩阵元素会变 0.2–0.4。分数、宽度、深度列一般到不了这个量级。这只是猜测，下面的诊断会验证。

## D1 逐列、逐种子比较（必须做）

在 cal_0067_0000 上，用现有 `infer_features.py` 的同一次前向结果，对比缓存，输出 `diagnosis_cal_0067_0000.json`：
1. pred 每一列（0 分数、1 宽度、2 高度、3 深度、4–12 旋转、13–15 中心、16）的最大绝对误差；
2. 有任何列差 > 1e-5 的种子数，以及这些种子在 `per_pose/train_0067_0000.npz` 候选里的个数；
3. `grasp_top_view_inds` 与缓存 `view_index` 不一致的种子数（全部 / 候选内）；
4. `depth_index` 不一致数；中心（13–15 列）最大误差；
5. 对视角一致的种子，pred 的最大误差（看剩下的差异是否只是浮点级别）。

## D2 同卡确定性（必须做）

在 A100 上对同一输入连跑两次，报告两次 pred 的最大误差。用来区分"跨显卡差异"和"本身不确定"。

## 按 D1/D2 的结果走（规则现在定死）

**情形 A：中心全部一致（≤ 1e-6），差异集中在少数种子的视角翻转，视角一致的种子误差 ≤ 1e-4，且 D2 两次一致。**
→ 在 cal、C3、P2 的复现前向中，**用缓存的视角覆盖网络的视角选择**：给 `net.view` 加 forward_hook，把 `end_points['grasp_top_view_inds']`、`['grasp_top_view_xyz']`、`['grasp_top_view_rot']` 替换为缓存中的 `view_index`、`view_xyz`、`view_rotation`（同设备、同 dtype）。这样柱状分组和抓取头看到的正是缓存姿态的那个视角，导出的特征与已算好的标签对应同一个抓取。
→ 新的复现门槛（替代原来的整体 1e-5）：对 per_pose 中的候选，
- 中心与缓存差 ≤ 1e-6；
- 视角编号完全一致（覆盖后应自动满足）；
- angle_index 完全一致；
- 角度 logit 与缓存 `angle_logits[:12]` 最大误差 ≤ 1e-2（C3 另与 I1 文件比较，同样 ≤ 1e-2）；
- pred 的分数列不作要求（标签不依赖分数）。
任何一帧不满足就停。每帧收据记录覆盖前的视角翻转数和覆盖后的 logit 最大误差。
→ 小头训练帧（probe）不受影响：它们是这次新推理，标签直接用这次的 pred 计算，不需要覆盖。

**情形 B：中心有差异（种子点变了），或 D2 同卡两次都不一致。**
→ 不要继续，把 D1/D2 结果推上来，我再定方案（可能改为 cal/C3/P2 也全部重新推理并重新评价）。

**情形 C：以上都不像（例如差异在分数或宽度列）。**
→ 同样停下，把 D1/D2 结果推上来。
