# 导出指令：只用相机看得见的点算"观测版 I1"（单视角牢度信息上限测试）

日期：2026-10-24。配套预注册：`eg_geom_ceiling_prereg_20261024.md`。
**只用 CPU，不推理，不训练，不做任何换角统计，不访问 C4/C5，不改任何历史目录。**

## 0 做什么

对 v3 导出里 cal、C3、P2 三个 split 的每一个角度变体（共 144 帧），只用这一帧的深度图（整幅、不用 GT 分割），沿两根手指的闭合线找观测点、估表面法向，按和 I1 完全相同的公式算一个"观测版 I1"。同时为诊断补算 GT 接触点在相机坐标系下的位置。本地拿到后用冻结代码判定，服务器端不计算任何与 μ、牢度或碰撞相关的统计。

## 1 分支与输入

- 新分支 `codex/eg-geom-ceiling-20261024`，从 `codex/eg-firmness-export-20261024`（05affc0）拉出；输出放 `obs/`。
- 姿态：直接用 `v3/eval/{split}_{s:04d}_{f:04d}.npz` 里的 `pred`（n×12×17，GraspGroup 格式），不重新生成：
  - 宽度 `w = pred[...,1]`，深度 `d = pred[...,3]`，旋转 `R = pred[...,4:13].reshape(3,3)`，平移 `T = pred[...,13:16]`；
  - `R[:,0]` 是接近方向，`R[:,1]` 是闭合方向。
- 帧：cal（场景 67, 4, 50, 56, 14, 65, 62, 30, 45, 1, 96, 71）、C3（100, 106, 115, 124, 132, 139, 150, 157, 160, 169, 176, 186）帧 0/64/128/192，P2（同 C3 场景）帧 32/96/160/224。probe split 不做。
- 相机、深度图、内参、深度因子与 v3 相同（N0 的设置）。

## 2 每帧步骤

1. **点云：** 深度图全部 depth>0 的像素，用与 N0 `get_inputs` 相同的反投影得到相机坐标系点（不做工作空间裁剪，不用分割，和 v3 第 5 步算 R1 时的整幅点云一致）。保留每个点的像素下标，供第 7 步查分割标签。
2. **去飞点：** 统计离群点去除，等价于 Open3D `remove_statistical_outlier(nb_neighbors=20, std_ratio=2.0)`。之后所有步骤都只用去除后的点云 `P`，建 KD 树。
3. **法向（只在需要的点上算）：** 对点 p，取 `P` 中 1 cm 半径内的邻点；少于 10 个则 p 不能用。否则做 PCA，取最小特征值对应的特征向量为法向 n，翻转使 `n·(−p) > 0`（朝向相机，相机在原点）。
4. **管道内的点：** 对每个候选 i、角度 k，用该变体的 (R, T, w, d)：
   - 先用 KD 树取 `T + d·R[:,0]` 周围 `w/2 + r + 1 mm` 内的点，再变换到抓取坐标 `t = (p − T) @ R`；
   - 管道条件：`|t_x − d| < r`，`|t_z| < r`，`|t_y| ≤ w/2`；
   - 去掉第 3 步判定"不能用"的点。
   - r 取 **3 mm（主）**，另报 2 mm、5 mm。
5. **找接触点：**
   - 管道里没有点：`found = 0`。
   - 取 `t_y` 最小的点 a、最大的点 b。若 `t_y(b) − t_y(a) ≥ 5 mm`：`found = 2`，接触 0 = a，接触 1 = b。
   - 否则 `found = 1`，只有一侧：法向满足 `n·R[:,1] < 0` 记为接触 0（取 a），否则记为接触 1（取 b）。
6. **观测版 I1（公式与 `evaluate_p2.py` 第 34–36 行逐字相同）：**
   - `found = 2`：`axis = (p1 − p0)/|p1 − p0|`，`cos = [n0·(−axis), n1·axis]`，`I1obs = mean(0.5·(1 − cos))`；
   - 否则 `I1obs = NaN`。
   - 另存 `I1half_r3`（只报告）：`found = 2` 时等于 I1obs；`found = 1` 时接触 0 用 `0.5·(1 − n·(−R[:,1]))`、接触 1 用 `0.5·(1 − n·R[:,1])`；`found = 0` 时 NaN。
7. **只报告的分割版：** r = 3 mm，但第 4 步只保留分割标签等于该候选物体的像素点（标签与 object_id 的对应与官方评价同一约定，在 summary 里写明用的是哪种对应）；法向仍用第 3 步在整幅 `P` 上算的。得到 `I1obs_seg_r3`、`found_seg_r3`。
8. **GT 接触点（只用于诊断，不进入任何判定）：** 对 v3 里 I1 有值的变体，用 `evaluate_p2.py` 同一个 `close_fingers` 调用重算接触点（物体坐标系），用该帧官方评价所用的物体位姿变换到相机坐标系，得到 `gt_pts_cam`。同时用重算的接触点和法向按第 6 步公式重算 I1。

## 3 输出

`obs/{split}_{s:04d}_{f:04d}.npz`，行顺序与 v3 评价文件完全一致：

| 字段 | 形状 | 说明 |
|---|---|---|
| candidate_id, original_angle | n | 从 v3 评价文件原样复制 |
| I1obs_r2, I1obs_r3, I1obs_r5 | n×12 | 第 6 步，NaN = 找不到两侧 |
| found_r2, found_r3, found_r5 | n×12 int8 | 0/1/2 |
| I1half_r3 | n×12 | 只报告 |
| I1obs_seg_r3, found_seg_r3 | n×12 | 只报告 |
| obs_pts_r3, obs_normals_r3 | n×12×2×3 | 按侧存放（下标 0 = 接触 0），缺失为 NaN |
| gt_pts_cam | n×12×2×3 | 第 8 步，缺失为 NaN |

## 4 核验（任何一条不满足就停，报告后等待）

先在 `C3_0100_0000` 和 `cal_0067_0000` 上跑通并核验，再跑全部 144 帧；全部帧也要汇总同样的核验。

1. **约定一致：** 在 GT 两侧接触都存在的变体中，至少 99% 满足：
   - 两个 GT 接触点到闭合线 `T + d·R[:,0] + s·R[:,1]` 的距离都 ≤ 1 mm；
   - `t_y(GT 接触 0) < t_y(GT 接触 1)`；
   - 两点的 `|t_y| ≤ w/2 + 1 mm`。
   不满足说明闭合线或接触顺序的约定和官方不一致，停止。
2. **I1 复算：** 第 8 步重算的 I1 与 v3 评价文件的 I1 缺失位置完全相同，最大绝对误差 < 1e-7。
3. **对齐：** 每帧 obs 文件的 candidate_id、original_angle 与 v3 评价文件完全一致。
4. **可重复：** `C3_0100_0000` 连跑两次，所有字段逐位一致。

## 5 交付

推送后报告提交号和 `obs/summary.json`，只含：
- 各 split 帧数、候选数、变体数；
- 去飞点删除比例（平均、最大）；
- r = 2/3/5 mm 时全部变体中 found = 0/1/2 的比例；
- 第 4 节 4 项核验的结果（含 99% 那一项的实际比例）；
- 分割标签对应方式、CPU 核数和总耗时。

**不报告任何与 μ、牢度、碰撞、换角有关的数字，不算相关。** 判定在本地用冻结代码 `eg_geom_ceiling_20261024/geom_ceiling.py` 完成。

参考成本：144 帧，去飞点每帧约 5–10 秒；管道查询约 8 万个变体，很快；GT 接触重算约 8 万次 `close_fingers`，12 进程约 10–20 分钟。不需要 GPU。
